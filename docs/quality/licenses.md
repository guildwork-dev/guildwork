# Licenses

Guildwork is licensed under the Apache License 2.0. This file describes how the repository keeps that true for its own files, for code taken over from elsewhere and for its dependencies. The license of each tool of the toolchain, read at the source with the retrieval date, is in [toolchain.md](toolchain.md#licenses).

## The project license

- `LICENSE` is the unchanged text of the Apache License 2.0. The license gate compares it byte for byte with the SHA-256 in `quality/licenses/license.sha256`.
- `NOTICE` names the project and its license. `THIRD_PARTY_NOTICES` lists every shipped third party component and every adopted file with license and copyright; it is generated by `make notices` and never edited by hand.
- Contributions come under the Developer Certificate of Origin 1.1 (sign-off on every commit) and the inbound terms of section 5 of the Apache License; there is no contributor license agreement ([CONTRIBUTING.md](../../CONTRIBUTING.md)).

## SPDX headers

Every hand-written file starts with the project header in the comment syntax of its type, within the first lines of the file:

```text
SPDX-License-Identifier: Apache-2.0
SPDX-FileCopyrightText: The Guildwork Authors
```

The header text, the comment form per file type and the line limit live only in `tools/ci/spdx_header.py`. Files that must stay verbatim or have no comment syntax are listed in `[exempt]` of `quality/licenses/header.toml`.

**Adopted code and prompts** keep the SPDX header of their source and add an `Origin:` line (`<owner>/<repo>@<commit>:<path>, modified`). The source license must be on the allowlist; a file under another license needs its own entry in `[[adopted]]` of `header.toml` with the reason. Every SPDX identifier that a header or a runtime dependency uses has its text in `LICENSES/<identifier>.txt`.

## Dependencies

| Kind | Rule | File |
|---|---|---|
| Runtime dependency (shipped) | license expression satisfied by the allowlist | `quality/licenses/allowed.txt` |
| Development dependency or tool (never shipped) | allowlist, or an entry `<name>@<version>` with license and reason | `quality/licenses/dev-exceptions.txt` |
| Claude Code, its platform packages and the Agent SDKs | never in a lockfile; Guildwork does not ship proprietary software (ADR-39) | `tools/ci/license_check.py` (`FORBIDDEN_NPM`, `FORBIDDEN_PYPI`) |

GPL, AGPL, SSPL and BUSL are never added to the allowlist; using such a component needs a separate decision with its reason. Container image contents and services of the compose bundle follow the same allowlist.

**Adding or updating a dependency:**

1. Read the license of the exact version at the source (registry metadata, else the license file at the release tag) and add a row with source and date to [toolchain.md](toolchain.md#licenses) when it is a tool.
2. Pin the exact version; commit the lockfile.
3. Run `make licenses`. A license outside the allowlist fails as `runtime-license-not-allowed` or `dev-license-needs-exception`. For a development tool, add a line to `dev-exceptions.txt` with the reason; the key contains the version, so an update needs a new line.
4. Run `make notices` and commit `THIRD_PARTY_NOTICES` when it changes.

## The license gate

`make licenses` (`tools/ci/license_check.py`) is part of `make check` and of the CI job `security`. It checks the `LICENSE` checksum, the SPDX headers, the dependency licenses from `pnpm-lock.yaml` and `uv.lock`, the `LICENSES/` texts, the ADR-39 lockfile test and whether `THIRD_PARTY_NOTICES` is current. Its rule identifiers are listed in the docstring of the tool.

## ScanCode

`make scancode` scans the committed tree of `HEAD` with ScanCode Toolkit and checks every detected license against the allowlist and against `quality/licenses/scancode-exceptions.txt` (one file and one expression per entry, with reason). It is not part of `make check`; it runs before every release and before the repository becomes public (release checklist V6, [public-switch.md](public-switch.md)). How it runs is described in [toolchain.md](toolchain.md#scancode).
